# 19.10.2026 — уведомление о превышении контекстного лимита

## Изменения
- При постоянной ошибке `provider_context_budget_exceeded` экспертный worker вызывает result-aggregator для доставки понятного сообщения пользователю в Telegram.
- Обработан и второй путь: превышение лимита при финальном синтезе вызывает уведомление в рамках того же запроса к result-aggregator, без ожидания внешнего повторного запуска.
- Result-aggregator не меняет статус задачи `failed` и сохраняет подтверждение доставки в `task_finalizations` до best-effort записи события, чтобы ошибка журналирования не вызывала повторную отправку уведомления.
- Добавлены события `task_failure_notified` и `task_failure_notification_failed` для наблюдаемости результата уведомления.
- Добавлен GitHub Actions workflow `.github/workflows/ai-sistem-edge-checks.yml`, который выполняет Deno type-check трёх изменяемых runtime-функций при PR в `main`.

## Проверки
- Проверены схема таблиц `telegram_updates`, `task_finalizations`, `task_events` в подключённом Supabase-проекте: используемые поля существуют.
- Проверены изменённые участки кода, статусы задачи и оба пути превышения лимита по исходникам.
- Deno type-check успешно пройден для `ai-provider-worker`, `expert-worker` и `result-aggregator` в GitHub Actions run `39248891823`.
- Автоматические lifecycle/unit-тесты, интеграционные тесты и проверка доставки на отдельном Telegram-боте ещё не выполнены.
- PR #3 остаётся Draft и не слит. Production Edge Functions не развёртывались.

## Ограничения
- Успешный type-check подтверждает проверку типов, но не доказывает корректность runtime-поведения и доставку уведомлений.
- Доставка уведомления зависит от доступности Telegram API и настроенного `TELEGRAM_BOT_TOKEN`.
- Если Telegram API недоступен, записывается ошибка уведомления; отдельный автоматический механизм повторной доставки пока не реализован.
