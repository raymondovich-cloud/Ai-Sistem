# Coordinator 1.0

## Назначение

Coordinator принимает созданную задачу, определяет её первичный домен и назначает только релевантных AI-агентов.

На версии 1.0 классификация выполняется детерминированным keyword-router. LLM-провайдер не является частью Coordinator 1.0 и будет подключён отдельным слоем.

## Workflow

1. Telegram создаёт `pending` task.
2. `telegram-webhook` передаёт `task_id` в `coordinator-worker`.
3. Coordinator переводит задачу в `consulting`.
4. Coordinator сохраняется как `primary`.
5. Подходящие эксперты добавляются как `consultant`.
6. В `task_events` фиксируется `coordination_started`.
7. Следующий слой должен передать задачу выбранным агентам.

## Правило выбора

Coordinator не заставляет всех экспертов участвовать. Выбираются только роли, связанные с содержанием запроса. Если домен не определён, временно используется Developer как технический fallback.

## Безопасность

`coordinator-worker` не открыт для публичного вызова: он принимает запрос только с Authorization Bearer, равным серверному service-role ключу, доступному только внутри Edge Functions.

Service-role ключ не хранится в GitHub и не возвращается клиенту.

## Ограничения 1.0

- нет LLM-классификации;
- нет генерации ответа;
- нет вызова экспертных моделей;
- нет автоматической отправки ответа в Telegram;
- нет выполнения кода Developer;
- нет финального verification workflow.

Это намеренное промежуточное состояние архитектуры.
